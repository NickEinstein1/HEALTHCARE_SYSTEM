⚡ QUICK START (5 minutes)
================================================================================

1. Start backend
   cd unihealth-360
   docker compose up -d
   # Wait 30 sec for services to be healthy

2. Start Provider app
   cd unihealth-provider
   npm install
   npx expo start
   # Press 'a' for Android emulator

3. Start Patient 360 app
   cd unihealth-patient360
   npm install
   npx expo start

4. Test on device
   Scan QR code in Expo Go app, or press 'a' for emulator

================================================================================
🚀 PLAY STORE BUILD (10 minutes)
================================================================================

1. One-time setup
   eas init
   # Links to Google Play Console

2. Build both apps
   cd unihealth-provider && eas build --platform android --profile production
   cd unihealth-patient360 && eas build --platform android --profile production

3. Upload to Play Console
   Go to https://play.google.com/console
   For each app:
   - Create new app
   - Upload .aab file
   - Complete store listing
   - Submit to Internal Testing

4. Internal beta testing (1–2 weeks)
   - Invite 50 testers
   - Gather feedback
   - Fix issues

5. Production rollout
   - Staged rollout: 5% → 25% → 100%
   - Monitor health metrics
   - Ship it! 🎉

❓ FAQ
================================================================================

Q: Can I run these apps without the backend?
A: Yes! They work with mock API data for demo/testing. Real API requires backend.

Q: How long until production?
A: Frontend: ready now. Backend + testing + rollout: 8–12 weeks.

Q: Can I modify the design?
A: Yes! Design tokens are in unihealth-shared/tokens.ts. Update colors, fonts, spacing.

Q: How do I add a new screen?
A: Copy app/(tabs)/index.tsx, rename, and add to (tabs)/_layout.tsx routing.

Q: How do I test M-Pesa payment?
A: Use Daraja sandbox. Credentials in .env.example. Replace with live keys for production.

Q: Can I use the shared components in another project?
A: Yes! unihealth-shared is standalone. npm install it as a local package.

Q: What about iOS?
A: Same apps run on iOS with minimal changes. App Store setup is similar to Play Store.

Q: How do I handle errors?
A: React Query handles fetching. Toast notifications via react-native-toast-message.

Q: Can I add offline support?
A: Yes! Use react-query caching + AsyncStorage. Plan: 2–3 days.
