System overview

UniHealth is a role-based healthcare platform. After authentication, each user lands on a dedicated dashboard tuned to their job: clinicians manage encounters, nurses run the ward, patients access self-service records, and administrators govern the facility. Every screen in this manual was captured from the live pilot UI at 1440×900 resolution so layouts match what you will see in training and production.

RoleDashboard URLPrimary use
Doctor/dashboard/doctorSign-in, navigation, and every clinical workstation tab
Nurse / CO/dashboard/nurseWard operations, vitals, MAR, triage, and handover
Patient/dashboard/patientSelf-service health records, appointments, results, payments, and privacy controls.
Administrator/dashboard/adminFacility control, users, RBAC, AI monitoring, and system administration.
Laboratory/dashboard/labSpecimen workflow, test queue, imaging modalities, QC, and specialised lab modules.
Pharmacy/dashboard/pharmacyDispensing queue, verification, stock, KEMSA orders, and clinical pharmacy tools.
Staging tip: Run ./scripts/run_staging.sh (gateway on port 8100) and npm run dev in frontend/app before using the web UI. Hard-refresh if panels show offline.

Universal sign-in flow

All roles share a four-step pattern at /sign-in. Staff enter a professional ID, email, and password; patients use national ID, UniHealth PIN, and mobile number. Every path ends with multi-factor authentication before the dashboard launch screen.

  1. Select role — scroll the carousel and choose the tile that matches your job.
  2. Enter credentials — role-specific fields plus password policy (staff) or PIN (patient).
  3. Verify MFA — email OTP for staff, SMS OTP for patients; Practice 360 in demo environments.
  4. Launch dashboard — confirm success message, then open your role workspace.

The sections below repeat this flow with role-specific screenshots, then document every sidebar tab for that dashboard.

Tips & troubleshooting — Doctor

Recommended daily workflow

  1. Sign in and complete MFA.
  2. Review Today's Overview for KPIs and alerts.
  3. Work Patient Queue — set active patient per consult.
  4. Document in Clinical Notes; order labs, imaging, and Rx as needed.
  5. Check System Health if panels show offline data.

Common issues

IssueWhat to do
Blank panels / Failed to fetchStart ./scripts/run_staging.sh; hard-refresh; verify Vite proxy → :8100
AI risk unavailableSystem Health tab; verify /ai/risk-score endpoint
E-sign upload failsDisable ad-blockers; API path is /esign not /legal
Wrong patient in ordersRe-select from queue or ward first
